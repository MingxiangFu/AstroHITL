# Annotation drag and drop

> **中文说明**：把左侧样本拖到中间的类别图上，现在会显示新类别或把图片放进已有类别，并从左侧列表里拿走。

## Cause

The graph drop handler kept the event only when `event.target` was the `#graph` element. The relation SVG is a child that covers the whole canvas, so a drop on empty space hit that overlay and was ignored. No category was created, and the left list did not change.

After a category existed, a later drop still missed. The overlay, or a relation line, received the event instead of the category card. The card is positioned at its layout point and then shifted with a negative margin, so the drawn box is not that point. The handler never compared the pointer with the drawn box.

> **中文说明**：放下事件落在铺满画布的连线层上就被丢掉，也不会按画出来的类别框做判断。

## Fix

The overlay and each relation line cancel `dragover` and `dragenter` themselves, so the drop is allowed to fire. The graph then reads the sample index and hit-tests every category with `getBoundingClientRect`. Empty canvas asks for a name and creates a category. A point inside a drawn category adds the image to that category. The place response redraws the card and removes the sample from the left list. The thumbnail is not a separate drag source; the card carries the sample index.

> **中文说明**：连线层自己接受放下，空处新建类别，落在已画出的类别上则加入该类别。

## Verification

`conda run -n base python -m pytest` — 39 passed. `tests/test_annotation_drag_drop.py` loads the page script, drops a sample on the overlay, and checks that the category appears. A second drop on the margin-shifted part of that drawn card adds the next image and clears the left list. That check failed before the fix.

`scripts/run_web.py` listens on `127.0.0.1:5002` only.

> **中文说明**：39 项测试通过，服务只绑定本机 5002 端口。
